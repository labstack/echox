## When it occurs

A POST authenticated by a cookie or another credential that the browser sends automatically did not carry a valid CSRF token. The token was missing, malformed or expired, or it belongs to another session.

## Client handling

Reload the page to get a fresh form and token, then submit again. API clients can send an explicit header credential, which needs no CSRF token.

## Server correction

Check `Principal.Session` and retained `Config.Keys` across instances. Cookie-authenticated POSTs need the token issued for the same session.
