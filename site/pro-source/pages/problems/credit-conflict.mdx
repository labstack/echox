| 409 | Credit ID was already used with a different amount |

## When it occurs

A credit was submitted with a credit ID that was already used with a different amount. Quota checks the ID atomically before it changes the balance, so this request applied nothing.

## Client handling

To retry the original credit, resend it with the same ID and the original amount. Use a new ID for a new credit.

## Example response

The package may omit diagnostic text or return it empty. Operation references do not grant access. Custom handlers can replace the body.

## How to fix

Recover the original credit operation's amount and reuse its ID only with that amount. A genuinely new adjustment needs its own ID. Do not mint another ID to conceal an unknown earlier credit outcome.

## Response fields

### quota administration routes

- `code` (string, always): The stable code above.
- `type` (string, always): The exact type URI above.
- `title` (string, always): English title. Quota administration routes use their own titles for some codes.
- `status` (integer, always): The HTTP status of the response.

Notes:

- The members match the quota middleware's. The body ends with a newline. HEAD responses have no body.
- Returned by `POST /credits`.

### admin console

- `code` (string, always): The stable code above.
- `detail` (string, always): Always present and often empty. Contains safe display text without underlying errors.
- `status` (integer, always): The HTTP status of the response.
- `title` (string, always): The HTTP status text, unless the problem carries a classified title.
- `type` (string, always): The exact type URI above.

Headers:

- `Cache-Control` (always): `no-store` on every console problem response, together with the console's security headers.

Notes:

- Fields are written in key order. The body ends with a newline. The type URI uses `https://echo.labstack.com/pro/problems/` followed by the hyphenated code. HEAD responses have no body.
- Every 404 response is rewritten to `admin_not_found` with an empty `detail`.
- The console renders this ID in its own shape when a panel returns it as an `admin.Problem` outside an action commit. Its title is the console's status text, `Conflict`, unless a classified title is supplied.
- A credit action's conflict at commit is not a problem response: it is an application/json action result whose `audit.code` is `credit_conflict` and whose outcome is `refused`.
