## When it occurs

The request body is larger than the server accepts. Either the `Content-Length` header or the bytes actually read exceeded the limit.

## Client handling

Send a smaller body.

## Example response

If your application installs a custom handler, the body may differ.

## Server correction

If the API must accept larger bodies, raise `MaxBodyBytes` before deployment. After the response starts, the server cannot replace it with a 413.

## Response fields

### OpenAPI middleware chain

- `type` (string, always): The exact type URI above.
- `title` (string, always): The HTTP status text.
- `status` (integer, always): The HTTP status of the response.
- `detail` (string, optional): Explanation text. Left out when empty.
- `code` (string, always): The stable code above.

Notes:

- The limit is `MaxBodyBytes` (default 1 MiB). The default OpenAPI `ProblemHandler` writes RFC 9457 JSON with `type`, `title`, `status` and `code`.
- The chain does not read the body before authentication. If auth finds the overflow, quota charges nothing. If quota already checked the request, the charge stays, subject to its settlement policy. A handler that reads only part of the body may not detect overflow.
- Once the response starts, the chain passes a `*BodyTooLargeError` to `OnError`. It cannot replace the response with 413.
