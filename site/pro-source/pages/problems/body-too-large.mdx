## When it occurs

The request body is larger than the server accepts. The declared Content-Length or an actual bounded read exceeded the limit.

## Client handling

Clients should reduce their request body before retrying.

## Example response

The package may omit diagnostic text or return it empty. Operation references do not grant access. Custom handlers can replace the body.


## How to fix

Reduce the body to the configured limit. If the API intentionally accepts larger payloads, review and raise its explicit body bound before deployment. A committed response cannot be replaced by a later 413.

Notes:

- HEAD responses have no body.
- The declared Content-Length or an actual bounded read exceeded `MaxBodyBytes` (default 1 MiB). The default openapi ProblemHandler writes RFC 9457 JSON with `type`, `title`, `status` and `code`, using application/problem+json. HEAD has no body.
- The chain never pre-reads before authentication. An overflow found during Auth has no quota debit. Overflow after limit check retains the charge, subject to the operation's settlement policy. Partial reads may not detect overflow.
