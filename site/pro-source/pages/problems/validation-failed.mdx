## When it occurs

The OpenAPI validator or your application validator rejected the request before the handler ran.

## Client handling

Clients should correct their request before retrying.

## Example response

The package may omit diagnostic text or return it empty. Operation references do not grant access. Custom handlers can replace the body.

## How to fix

Correct the input that failed the operation's validator. Inspect only the application's projected field diagnostics. Retain the same execution key only when the corrected request is still compatible with that binding's fingerprint rules.

Notes:

- HEAD responses have no body.
- The validator rejected the request before the handler ran. A validator 404/405 for an Echo-matched operation also returns this problem. It reports a `MismatchError` once per operation. Handler errors are not converted.
- The default OpenAPI `ProblemHandler` writes RFC 9457 JSON with `Content-Type: application/problem+json`. It includes `type`, `title`, `status`, `code` and optional `detail`. `detail` contains the validator's first line without control characters, limited to 256 bytes. `HideValidationDetail` omits it. HEAD has no body.
- Body overflow takes precedence while the response remains uncommitted. Validation runs after quota checks. The request is charged according to its settlement policy.
