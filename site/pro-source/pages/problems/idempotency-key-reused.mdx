## When it occurs

The key already belongs to another request. This request's fingerprint differs from the first recorded request.

## Client handling

Do not change a request while you retry it under the same key. To get the original operation's answer, resend the original request with that key. Use a new key only for a new, different operation.

## Example response

The package may omit diagnostic text or return it empty. Operation references do not grant access. Custom handlers can replace the body.

## How to fix

Restore the original business request for that key. A different intended operation needs its own key after the application's duplicate-effect policy permits it. Check the route's fingerprint descriptor and business inputs.
