| --- | --- |
| 402 | Request cannot be satisfied as prepaid credits are insufficient |

## When it occurs

The prepaid credit balance does not cover the request's cost.

## Client handling

Add credits or reduce the request's cost before retrying. An unchanged request remains refused while its cost exceeds the available balance. `violated-policies` names the credits limit.

## Example response

The package may omit diagnostic text or return it empty. Operation references do not grant access. Custom handlers can replace the body.

## How to fix

Fund the correct prepaid balance or reduce the work cost. Check the trusted tenant, selected plan and meter before applying credits. Reuse a credit adjustment ID only with its original amount.

## Response fields

### quota middleware

- `code` (string, always): The stable code above.
- `type` (string, always): The exact type URI above.
- `title` (string, always): English title. Quota administration routes use their own titles for some codes.
- `status` (integer, always): The HTTP status of the response.
- `detail` (string, optional): Human-readable explanation, omitted when empty. Its wording is not a stable format.
- `violated-policies` (array, always): IDs of the limits involved: `[]` when there are none, never null. The hyphenated name is a legacy exception to the naming rule for new members.

Headers:

- `RateLimit-Policy`, `RateLimit` (conditional): Draft-11 rate-limit fields, sent by the middleware when `Headers` is `Draft11` (the default) or `Draft11AndLegacy` and the plan has a limit to report. `UsageHandler` does not send them.
- `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (conditional): Legacy rate-limit fields, sent by the middleware when `Headers` is `Legacy` or `Draft11AndLegacy`.

Notes:

- Optional members are omitted when absent, and the body ends with a newline. HEAD responses have no body.
