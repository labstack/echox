## When it occurs

The principal sent more console requests than its rate limit allows. Each principal gets separate default buckets for reads, writes and probes. Reads allow 10 requests per second with burst 30. Writes allow 12 per minute with burst 12. Probes allow six per minute with burst six. `Config.RateLimit` replaces these buckets. Middleware that returns HTTP 429 is reported with this code too.

## Client handling

Wait for the number of seconds in `Retry-After`, then retry. Reduce automated polling of the console.

## How to fix

Reduce console request frequency and respect the supplied retry advice. Avoid automatic view polling. A mutation retry keeps the same action ID after limit check becomes available.

## Response fields

### admin console

- `code` (string, always): The stable code above.
- `detail` (string, always): Always present and often empty. Contains safe display text without underlying errors.
- `status` (integer, always): The HTTP status of the response.
- `title` (string, always): The HTTP status text, unless the problem carries a classified title.
- `type` (string, always): The exact type URI above.

Headers:

- `Cache-Control` (always): `no-store` on every console problem response, together with the console's security headers.
- `Retry-After` (conditional): Whole seconds, at least 1. Sent when the console's rate limit, built in or `Config.RateLimit`, refused the request.

Notes:

- Fields are written in key order. The body ends with a newline. The type URI uses `https://echo.labstack.com/pro/problems/` followed by the hyphenated code. HEAD responses have no body.
- Every 404 response is rewritten to `admin_not_found` with an empty `detail`.
