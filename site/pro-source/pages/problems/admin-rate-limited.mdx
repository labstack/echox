## When it occurs

The principal sent more console requests than its rate limit allows. Each principal gets separate default buckets for reads, writes and probes. Reads allow 10 requests per second with burst 30. Writes allow 12 per minute with burst 12. Probes allow six per minute with burst six. `Config.RateLimit` replaces these buckets. The console also uses this code when `Config.Middleware` returns HTTP 429.

## Client handling

Wait for the number of seconds in `Retry-After`, then retry. Reduce automated polling of the console.

## Server correction

Reduce automated polling and check `Config.RateLimit`. Action clients must preserve the action ID when retrying.

## Response fields

### Admin console

- `code` (string, always): The stable code above.
- `detail` (string, always): The console always sends `detail`. It is often empty and never contains the underlying error.
- `status` (integer, always): The HTTP status of the response.
- `title` (string, always): The HTTP status text, such as `Conflict`, unless the panel supplies its own title.
- `type` (string, always): The exact type URI above.

Headers:

- `Cache-Control` (always): `no-store`. The console sends it on every problem response, along with its usual security headers.
- `Retry-After` (conditional): Whole seconds, at least 1. Sent when the console's rate limit, built in or `Config.RateLimit`, refused the request.

Notes:

- Fields are written in alphabetical order.
- The console rewrites every 404 response to `admin_not_found` with an empty `detail`.
