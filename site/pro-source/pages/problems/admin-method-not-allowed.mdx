## When it occurs

The console does not serve this HTTP method here. It serves GET and HEAD, and POST only when actions or POST reads are enabled. The console also uses this code when `Config.Middleware` returns HTTP 405.

## Client handling

Use a method that the `Allow` header lists.

## Server correction

Check the client's method and the endpoint's `Allow` header. Ordinary views use GET. Declared POST lookups, action preview and commit use POST.

## Response fields

### Admin console

- `code` (string, always): The stable code above.
- `detail` (string, always): The console always sends `detail`. It is often empty and never contains the underlying error.
- `status` (integer, always): The HTTP status of the response.
- `title` (string, always): The HTTP status text, such as `Conflict`, unless the panel supplies its own title.
- `type` (string, always): The exact type URI above.

Headers:

- `Cache-Control` (always): `no-store`. The console sends it on every problem response, along with its usual security headers.
- `Allow` (conditional): Methods the console serves: `GET, HEAD`, plus `POST` when enabled. Sent when the console's own method check refused the request.

Notes:

- Fields are written in alphabetical order.
- The console rewrites every 404 response to `admin_not_found` with an empty `detail`.
