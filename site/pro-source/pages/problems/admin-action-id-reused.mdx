## When it occurs

The console refused an action commit because it could not tie the commit to one consistent action. The confirmation token may be missing, malformed or invalid for this action and input. The receipt cache may hold different input under this `action_id`. The audit sink may also report the same action ID with different content.

## Client handling

When the confirmation does not verify, request a new preview and commit with the confirmation it returns. Do not reuse an `action_id` for different input. To retry the same action, resend the identical input with the same `action_id` and confirmation. For a new action, open a fresh form, which generates a new `action_id`.

## How to fix

Restore the original action ID and business input for a retry. If this is a different intended action, obtain a fresh preview and action ID. Do not change the ID merely because the previous mutation's response was lost.
