Echo Pro problems have an exact `type` URI and snake_case `code`. Match both fields when handling errors.
Titles and `detail` are display text. They can change or be translated.
An application can define its own absolute type URIs.
Reusing a built-in code with your own type URI does not create a built-in problem type.

## HTTP responses

Default responses use `Content-Type: application/problem+json`. HEAD responses have no body.
Each package defines its own extension fields and retry headers.
A status alone does not tell you whether a mutation applied.
Install `problem/echoadapter` as Echo's error handler for errors implementing `Problem() problem.Details`.
Keep the previous handler as fallback.
The adapter preserves existing `WWW-Authenticate`, `Allow` and `Retry-After` headers. It does not add permission to retry.

Quota denials include `violated-policies`.
Execution problems include `operation_ref`, `operation_state` and `safe_new_key`.
Console problems always include `detail`, which may be empty.
Your application can replace these bodies with custom handlers. Update clients if you change the response fields.

## Quota type URIs

Quota uses `https://iana.org/assignments/http-problem-types#quota-exceeded` for exhausted time budgets.
It returns 429 with code `quota_exceeded`. Respect `Retry-After` and inspect `violated-policies`.
Strict-store failures use `https://iana.org/assignments/http-problem-types#temporary-reduced-capacity`.
They return 503 with code `temporary_reduced_capacity` and a retry header.
An unavailable store does not mean the customer exhausted their budget.
These URI strings do not claim IANA registration.
