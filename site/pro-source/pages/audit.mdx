`echo.labstack.com/pro/audit` records who performed an application action and the outcome your application reported.
The [task guide](/pro/guides/audit/) shows wiring; the [reference](/pro/reference/audit/) lists fields and defaults.
These recorded facts are called audit evidence. They do not verify that your actor mapping or reported outcome is true.
Request logs alone do not describe the business action.

This route reads the system actor and route selected by audit middleware.
Recording an event also needs a schema and store, as shown in the [task guide](/pro/guides/audit/).

## Prepare an event once

`NewSchema` copies registered fields and their projection rules.
Register metadata names with their `redact.Class` before calling `Prepare`.
The default storage policy requires HMAC keys. Keep the immutable `redact.Keyring` available while using the schema.
An explicit mask fallback works without HMAC keys but prevents equality searches.
`Schema.MaskFallback()` reports whether that fallback is enabled.

Map the actor from the verified principal. Classify user and service IDs as identifiers.
System and anonymous actors may omit their IDs.
Choose tenant, action, target and metadata from trusted application state.
Do not let a client-supplied actor field decide who performed the action.

`Schema.Prepare` validates and copies the event into a `PreparedEvent` with serialized bytes and a digest.
It generates missing event IDs and occurrence times once per preparation.
Keep the prepared event for retries. Preparing again can create a different event.
Use one stable ID and identical content for each business event.

Invalid event fields return `*audit.ValidationError`.
Invalid schema or store configuration returns `*audit.ConfigError`; projection errors can return `*redact.ConfigError`.
Inspect types with `errors.AsType` and stable error values with `errors.Is`.

## Recording and business actions can fail separately

`Record(ctx, prepared)` records the event.
A successful `Record` does not put a preceding external effect inside a transaction.
If your policy requires a record before an action, record intent first. Stop the action when that recording fails.
Record the outcome afterward with the same `OperationID` and a distinct event ID.

An action can succeed while recording its outcome fails.
`*audit.OutcomeUnrecordedError` reports the recording failure and preserves the operation ID.
Do not repeat the business action because its audit outcome is missing.
The [capacity failure example](/pro/guides/audit/) demonstrates that case.

`MiddlewareConfig` supplies request scope and trusted actor mapping.
`DenialConfig` records rejected requests on the routes where you install it.
Put denial recording outside authentication and authorization so it can observe their refusals.
Denial recording runs synchronously and allows the existing refusal response through by default.
With fail-closed recording, `*audit.DenialUnrecordedError` replaces an uncommitted response if recording fails.
The rejected request still cannot reach the handler.

## Choose a store

`NewMemoryStore` requires event and byte capacities.
It returns `ErrCapacity` when full instead of deleting old events to make room.
It supports concurrent calls and loses records at restart. Use it for tests and local demos.

`auditpg` records on one writable PostgreSQL 16 through 18 primary.
Your application supplies and closes its pools.
Deployment requires a trusted NOLOGIN owner and separate recorder, relay, maintenance and reader roles.
`Migrate` requires those roles to exist; it does not create logins.
`New` validates ownership, helper permissions, primary database and transaction history.
It does not migrate or close the pool. Recording requires READ COMMITTED transactions.

Keep runtime roles separate from the deployment owner.
Poolers must preserve the permissions and database checks the package needs.
`audit_events` holds retained events; `audit_cursors` tracks relay progress.
`audit_meta` records schema and database history.
`audit_admin_bindings` deduplicates console emissions and annotations using their IDs and content digests.
Pruning an event also removes its associated deduplication record.

## Read, search and export

Authorize the exact tenant before `Reader.Get`, `Query` and each continuation.
A pagination token does not grant access. Keep the query filter unchanged across pages.
Time ranges include the start and exclude the end. Times normalize to UTC microseconds.

Search probes use the schema and retained keys to derive equality tokens.
Keep probe values and database parameters out of logs and URLs.
Retain projection keys while you need to search the corresponding records.

Exports write retained records and a trailer to your writer.
The export example reports `integrity=unauthenticated`. That output does not provide a signed chain.
Use an authorized access recorder when your export policy requires an audit trail.
`SlogExporter` writes projected records to your logger and reports its output format.

## Restore and operate

Restoring a database can lose recently recorded events.
`auditpg` checks the cluster, transaction history and persisted progress markers.
A detected rewind requires reviewed `Rebind` or `Fork` input documenting the restore.
An error does not authorize discarding progress markers or restarting under another database ID.
Your application schedules retention and relay work.

`auditadmin` exposes an authorized reader in the [console](/pro/admin/).
The [full demo](/pro/recipes/admin-demo/) uses memory audit storage when its login lacks the required PostgreSQL roles.
That mode demonstrates the UI and does not test durable audit storage.
[Execution](/pro/execution/) tracks uncertain external sends; audit records what the application reports about them.
