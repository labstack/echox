## Goal

Run one local Echo application and observe its authentication, tenant selection and quota checks. Queue a signed `invoice.created` event and inspect tenant usage in the embedded console. This tutorial uses memory stores. All key, usage and webhook state disappears when the process exits.

## Prerequisites

Complete [installation](/pro/install/) in an application module using Go 1.26 or later. Port 8080 must be free on loopback. Have `curl` and a browser available. You do not need Redis, PostgreSQL or a frontend build. Pick a file path that does not exist yet. The program writes a disposable API key there.

## Step 1: start the application

From your application module directory, find the installed module directory:

```sh file=site/pro-source/examples/site-docs/commands.sh#module-directory
```

Run its compiled example:

```sh file=site/pro-source/examples/site-docs/commands.sh#getting-started
```

The program writes the key to that path with mode 600. It exits with an error if the file already exists. It prints the API URL ending in `/v1/tenants/acme/invoices` and the admin URL. Keep this terminal running. The key is restricted to `acme` and has invoice read/write and admin-read scopes. The pepper exists only in memory, so the key stops working when the process exits.

With `-browser`, browser requests whose Host is exactly `127.0.0.1:8080` get read-only console access. Any local user or process that can reach that address gets the same access. In a deployed application, replace it with your own login.

## Step 2: check authentication

In another terminal, make an unauthenticated request:

```sh file=site/pro-source/examples/site-docs/commands.sh#unauthenticated
```

Expect HTTP 401 and `Content-Type: application/problem+json`. The authentication guard rejects it before tenant selection, quota or the invoice handler runs.

Send the key as a header. curl reads the header from standard input (`--header @-`), so the key never appears in command arguments:

```sh file=site/pro-source/examples/site-docs/commands.sh#authenticated
```

Expect HTTP 200. The JSON contains tenant `acme` and invoice `inv-1`. This request uses 1 of the 3 requests the `free` plan allows per UTC day.

## Step 3: verify tenant isolation

Use the same key on a different tenant path:

```sh file=site/pro-source/examples/site-docs/commands.sh#cross-tenant
```

Expect HTTP 403. The URL names a different tenant from the one the key is restricted to. This refusal does not count against the quota. Editing the URL does not let a key reach another tenant.

## Step 4: queue an event

Create a demonstration invoice:

```sh file=site/pro-source/examples/site-docs/commands.sh#create-invoice
```

Expect HTTP 202 with `invoice` and `webhook_ref` fields. The generated invoice ID changes each run. This request uses the second of the three. The handler queues an immutable event. Its webhook ID is derived from the invoice ID. The local worker signs it and sends it to the loopback receiver.

The server terminal prints `Webhook delivered: verified invoice.created` after verification. The receiver verifies the signature over the raw request body. It does not store invoices or skip duplicate events. The 202 returns as soon as the event is queued. It does not wait for delivery.

## Step 5: exhaust the daily quota

Repeat the authenticated GET from Step 2 once. It returns 200 and uses the third unit. Repeat it again. The fourth authenticated request returns HTTP 429 with code `quota_exceeded`. Its `type` is `https://iana.org/assignments/http-problem-types#quota-exceeded`. The `violated-policies` field names the limit that was exceeded. Use `reset_at` for the next UTC day. Daily limits do not send `Retry-After`. The 401 from step 2 and the 403 from step 3 did not count.

The counter follows a UTC day. Restarting this memory-only demo clears its usage. In a deployment, use the [Redis or Valkey store](/pro/guides/quota/). It shares the budget across instances, and a restart does not reset it.

## Step 6: inspect and stop

Open `http://127.0.0.1:8080/admin`. Select Quota, then Usage, with tenant `acme` and plan `free`. The panel reads usage from the limiter the API uses. It does not consume a request. This console has no write actions.

Press Ctrl-C in the server terminal. HTTP serving stops first. The program then waits for the webhook worker to stop and for pending quota settlement to finish.
Finally, it removes only the key file it created. If the process crashes, the file stays. Delete it before you restart with the same path.

## Change for deployment

Replace `MemoryKeyStore` with a store implementing `Lookup(context.Context, string) (auth.StoredKey, error)`.
See the [compiled lookup example](/pro/guides/auth/#replace-the-memory-key-store).
Your store must return current revocation data. Load peppers from your secret manager. Keep authentication and tenant checks ahead of quota. Choose the plan from your subscription records, not from request data. Use `redisstore` for shared budgets.

Use `webhookpg` to keep inbox and outbox state in PostgreSQL. Give each business effect a permanent key, such as the invoice ID, stored in your own table. Keep receiver deduplication records for as long as the sender can resend an event. Replace the demo's injected console credential with your login sessions. List exact allowed origins. The [package explanations](/pro/auth/) and [full console tutorial](/pro/recipes/admin-demo/) explain storage and operator requirements.
